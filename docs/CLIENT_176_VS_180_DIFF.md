# 1.76 客户端 vs 1.80 客户端资源差异分析

> 分析日期：2026-11-11　执行环境：`D:/Python310/python.exe`（3.10.11）
> 对比脚本：`scripts/compare_client_versions.py`　明细数据：`data/client_diff_176_180.json`
> 范围：`Data/`（图库 WIL/WIX 与杂项）、`Map/`（.map）、`Wav/`（.wav + sound.lst）

## 0. 结论速览

- **1.80 是 1.76 的严格增量超集**：按文件名（大小写不敏感）对齐后，1.76 **没有任何独有文件**；差异只有「1.80 新增」和「同名文件被改动」两类。
- 规模：文件数 `1167 → 1509`，资源体积 `955.4 MB → 1558.6 MB`（+63%）。新增 **16 组图库 / 128 张地图 / 179 个音效**；改动 **14 组图库 / 2 张地图 / 5 个音频文件**。
- **28 组图库、526 张地图、540 个音效字节级完全一致**（MD5 相同）。说明 1.80 沿用了 1.76 的绝大多数原始素材，属于官方增量升级，而非私服自定义替换；1.76 可作为校验 1.80 资源是否被魔改的基准。
- **1.76 不能直接替换现有 `resources/`**：项目自带体检工具判定 1.76 为「不可用」——缺 `prguse3`（F10 装备页底图）、缺 `mon19/20/21`、`Weapon.wix` 索引表短 4 字节。1.80 判定「可用」，关键帧 4/4 命中。
- **最隐蔽的差异是 BGM 文件名对调**：1.80 把 `log-in-long2.wav` ↔ `game over2.wav`、`main_theme.wav` ↔ `sellect-loop2.wav` 两组曲子的内容互换了名字（MD5 交叉验证）。这正是项目 §17 需要把 `intro/gameover` 索引对调的根因；若换回 1.76 的 Wav，索引也必须换回来。

## 1. 数据源与校验方法

| 侧 | 目录 | 说明 |
|---|---|---|
| 1.76 | `client_original/传奇1.76客户端/传奇私服1.76客户/` | 本次新放入，`Data/ 94` + `Map/ 528` + `Wav/ 545` |
| 1.80 | `resources/` | `Data/ 129` + `Map/ 656` + `Wav/ 724`；另有项目后处理产物 `Audio/ 723 mp3`、`resources.json` |

- **来源完整性**：用 7-Zip 列出 `传奇1.76客户端.rar` / `传奇1.80纯净客户端.rar` 清单，与磁盘按「文件名 + 原始大小」逐项核对，三个资源目录均为 **rar 独有 0 / 磁盘独有 0 / 大小不符 0**。即 `resources/` 确实是 1.80 客户端的完整提取，1.76 解压目录也完整；本次对比不是拿残缺目录在比。
- **文件级**：文件名小写对齐 → 比大小 → 大小相同再算全文件 MD5；独有文件也记 MD5，用于找「换名复用」。
- **图库**：按 `scripts/verify_resources.py` 的约定解 WIX（`imageCount` @44、偏移表 @48、WIL 头 1080 字节），并进一步按 WIX 偏移区间对**每一帧**做 MD5 切片比对，区分「尾部追加」与「帧号重排」。
- **音频**：`wave` 模块读声道/采样率/位深/帧数；**地图**：读 52 字节头的宽高并按 12B/tile 换算差异落点。
- 未纳入对比：客户端程序文件（`Mir.exe`、dll、`*.dat` 根目录配置等，1.80 侧只保留了程序目录、资源已抽出）、两个 `.rar`、`Audio/*.mp3`（项目转码产物）、`resources.json`（项目索引）。

## 4. 音频差异

- **数量与时长**：544 → 723 个 wav，总时长 `949.7 s (15.8 min) → 1481.8 s (24.7 min)`。主流格式 44.1 kHz / 16 bit：单声道 375 → 467、立体声 166 → 252；1.80 新增 1 个 11 025 Hz / 8 bit 文件。
- **两组 BGM 内容对调（MD5 交叉验证，非重新编码）**：

| 文件 | 1.76 内容 | 1.80 内容 | 1.76 内容在 1.80 的落点 |
|---|---|---|---|
| `log-in-long2.wav` | 68.564 s（开场曲） | 34.261 s（死亡曲） | `game over2.wav` |
| `game over2.wav` | 34.261 s（死亡曲） | 68.564 s（开场曲） | `log-in-long2.wav` 及新增别名 `game-over2.wav` |
| `main_theme.wav` | 43.886 s / 22 050 Hz | 35.973 s / 44 100 Hz | `sellect-loop2.wav` |
| `sellect-loop2.wav` | 35.973 s / 44 100 Hz | 43.886 s / 22 050 Hz | `main_theme.wav` |

`sound.lst` 同时从 14 155 B 扩到 18 660 B。**项目 §17 记录的「intro/gameover 索引对调」正是 1.80 文件名语义变化的直接后果**：Delphi 的曲目编号常量未变，变的是文件里装的内容。若改用 1.76 的 Wav，必须把该对调还原，否则开场会放死亡曲。

- **179 个新增音效分类**：

| 类别 | 数量 | 说明 |
|---|---:|---|
| `2xxx-N.wav` | 123 | 新怪物组叫声（攻击/挨打/死亡等动作后缀 0~8），对应 `mon19~23`/新 appr |
| `mXX-N.wav` | 39 | 怪物叫声补档（`m38`~`m55`、`m100/101`） |
| 纯数字 `122/123/124.wav` | 3 | 编号音效补档 |

项目 `SoundManager` 按 `Appr×10+200` 映射怪物叫声并对缺失资源自动静默，换 1.76 会导致这批新怪集体无声。另有 **7 组换名复用**（如 1.80 `2100-2.wav` = 1.76 `2101-3.wav`、1.80 `m49-0.wav` = 1.76 `m13-1.wav`），说明部分新增只是旧音效重命名/复制。

## 5. 地图差异

- **526 / 528 张同名地图字节级完全一致**，只有 `0.map`、`1.map` 内容变化且大小不变：

| 地图 | 尺寸 | 差异字节 | 涉及 tile | 差异位置 |
|---|---|---:|---:|---|
| `0.map` | 700×700 | 4831 | 2040 | tile 索引 160264~282303，坐标约 x 580~672 / y 228 起 |
| `1.map` | 600×600 | 1955 | 872 | tile 索引 78582~139728，坐标约 x 580~588 / y 130 起 |

差异集中在 12 B tile 结构的第 `0/1/4/5/10` 字节（背景/对象图层索引字段），是局部图块编号改写，不是整图重做；与 `Tiles/Objects` 图库扩容的方向一致（推断，未做逐格像素比对）。

- **128 张新增地图按前缀**：`em` 64（30×35 活动模板图，带附加数据块）、`h` 18、纯数字 15（`6/61~66/611~632/1111` 等）、`n` 14、`ev` 4、`ga` 4、`d` 3、`k` 3、`b357 / hero001 / s001` 各 1。
- tile 步进：1.76 `12B×525` + 带附加数据 3 张；1.80 `12B×590` + 带附加数据 66 张（其中 64 张是 `em000~em063`）。
- **覆盖率没有提升**：`gamedata/Mir200/Envir/MapInfo.txt` 登记 445 张，1.76 与 1.80 各缺 **同样的 71 张**（`T0000~`、`M995` 等）。新增的 128 张不在当前服务端登记里，属于客户端预置的活动/模板图。

## 6. 对 jootm2 的实际影响

`scripts/verify_resources.py` 的体检结果：

| 项 | 1.76 | 1.80（`resources/`） |
|---|---|---|
| 结论 | **不可用** | 可用 |
| 图库 | 42 组，缺基础库 `prguse3`，缺怪物库 `mon19/20/21` | 58 组，无缺失 |
| WIX 异常 | 1 个（`Weapon.wix` 短 4 B） | 0 |
| 关键帧抽查 | 命中 3/4 | 命中 4/4 |
| 地图 / 音效 | 528 / 544（MapInfo 缺 71） | 656 / 723（MapInfo 缺 71） |

项目当前所有硬编码都按 **1.80** 语义：`resources.json` 登记 58 组图库 / 656 地图 / 723 音效；UI 帧号（`prguse[370]`、`prguse3[29]`）、怪物 appr→图库/叫声映射、小地图 1-based 索引、BGM 索引对调等，均以 1.80 为准。

**建议**

1. **继续以 `resources/`（1.80）为运行基准**，不要整体替换成 1.76；否则 F10 装备页、新怪显示与叫声、大量 UI 贴图会直接缺失或错位。
2. **把 1.76 当作校验基准**：28 组图库 / 526 张地图 / 540 个音效与 1.80 逐字节相同，可证明现有资源未被私服替换；排查「与原版不一致」时，若涉及这些共有资源，两版等价，可放心用本地 1.76 或 Delphi 源码做依据。
3. 若将来要做「1.76 模式」，至少需：补 `prguse3` 或改 UI 帧号、修 `Weapon.wix` 末项、`mon18` 帧号重映射、`mon19~23`/新技能/新音效缺省兜底、地图与 BGM 索引分开配置。建议按 `resources.json` 做版本化资源清单，而不是替换目录。
4. 结论边界：本次是**文件与帧结构层面**的对比，未做逐帧像素观感比对；`em*` 模板图的附加数据块、`lig0*.dat` 等配置语义未展开。
