## 重点摘要

1. **6 个技能的等级门槛与项目 `Magic.csv` 全部一致**（7/11/16、19/22/24、25/27/29、28/31/34、30/34/39、35/37/40），再次确认项目数据表就是经典 `Magic.DB`。
2. **数值公式与火炬源码逐条对得上**：攻杀 `5+lv`、基本剑术 `3×lv` 准确、刺杀 `dam/5×(lv+2)`、半月 `dam/13×(lv+2)`、烈火 `×(1.4/1.8/2.2/2.6)`——项目这 5 项实现均正确。
3. **烈火剑法：项目 2/3 级各低 1 点**。官服 53 攻击下是 74/95/117/138，项目算出 74/95/**116**/**137**，原因是 `java_div` 截断而原版用 `Round`（`dam×HitDouble/10`）。
4. **野蛮冲撞：项目每级少走 1 格**。原版 `for i:=0 to _MAX(2, rushlevel+1)` 实际是 3/3/4/5 次移动，视频也印证「完整冲撞前进 5 格」；项目 `range(max(2, lv+1))` 只有 2/2/3/4。
5. **半月「主目标不破防则剑气无效」两版口径冲突**：本视频（官服）说有此门槛，996 视频（BV1Dxxs6QE3e）说没有；火炬源码 `ObjBase.pas:5405-5411` 在扣 AC **之前**就结算剑气，属「无门槛」，项目与火炬一致——**不建议改**。

## 与项目实现的差异清单

### P1-1 野蛮冲撞步数少 1 格

原版 `ObjBase.pas:5783`（`TCreature.CharRushRush`）：

```pascal
for i:=0 to _MAX(2, rushlevel+1) do   // 0..N 共 N+1 次
```

`rushlevel` = 技能等级 0~3，所以迭代次数是 **3 / 3 / 4 / 5**。视频「一个完整的野蛮冲撞可以向前移动五个位置」正是满级那 5 格。

项目 `handlers_combat.py:912`：

```python
max_steps = max(2, lv + 1)      # 2 / 2 / 3 / 4
for _ in range(max_steps):
```

**每个等级都少 1 格**（满级 4 格 vs 官服 5 格）。改为 `max(2, lv + 1) + 1` 即可对齐；因为涉及 PK 手感与堵门战术，属于[调整]范畴，需你确认后再动。

### P1-2 野蛮冲撞缺「三级同时撞 2 个目标」

原版 `ObjBase.pas:5788-5796`：`rushlevel >= 3` 时先检查正前方 **第 2 格**，若那里也有可撞目标就先把它推 1 格，再推第 1 格。项目 `_rush_rush` 只处理第 1 格。

### P1-3 野蛮冲撞不能撞玩家

原版 `CanPush` 只判 `Abil.Level > cret.Abil.Level` + `IsProperTarget`，玩家同样可被撞；视频也明说「可以撞比自己等级低的玩家和怪物」。项目 `_rush_rush` / `_push_around` 都写死了 `isinstance(a, Monster)`，**只推怪**。

同类问题在法师篇已记录（抗拒火环只推怪）——根因是 PvP 位移缺少客户端表现与 PK 保护，属于已知取舍，不是漏写。

### P2 烈火剑法 2/3 级各低 1 点（Round vs 截断）

原版 `ObjBase.pas:5372`：

```pascal
dam := dam + Round (dam / 100 * (HitDouble * 10));   // HitDouble = 4 + lv*4
```

项目 `handlers_combat.py:409`：

```python
bonus = java_div(dam_ref * (4 + lv * 4), 10)   # 向零截断
```

以视频的 53 点攻击为例：

| 等级 | 原版 Round | 项目截断 | 官服实测 |
|---|---|---|---|
| 0 | 21.2 → 21（总 74） | 21 → 74 | **74** |
| 1 | 42.4 → 42（总 95） | 42 → 95 | **95** |
| 2 | 63.6 → **64**（总 117） | 63 → **116** | **117** |
| 3 | 84.8 → **85**（总 138） | 84 → **137** | **138** |

改成 `java_round(...)` 即可，误差仅 ±1 点，影响很小但确实是偏差。

### 无差异项（已核对，勿动）

- 基本剑术 `Round(9/3×lv)`、攻杀 `Round(3/3×lv)` 命中加成 —— `ObjBase.pas:4256-4262`。
- 攻杀 `HitPowerPlus := 5 + Level`（5/6/7/8）与伪随机计数 `AttackSkillCount := 7 - Level` —— `ObjBase.pas:4265-4267`、`:9328-9335`。
- 刺杀 `dam / (MaxTrainLevel+2) × (Level+2)` = `/5` —— `ObjBase.pas:5400`。
- 半月 `dam / (MaxTrainLevel+10) × (Level+2)` = `/13` —— `ObjBase.pas:5409`；扫 3 个方向 `(Dir+7, Dir+1, Dir+2) mod 8` —— `:5279-5297`，与项目 `_sword_wide_attack` 完全一致。
- 烈火 10 秒冷却 `GetTickCount - LatestFireHitTime > 10*1000` —— `ObjBase.pas:2942`。
- 野蛮伤害 `(1+damagelevel)*4 + Random((1+damagelevel)*5)`、成功率 `Random(20) < 6+rushlevel*3+levelgap` —— `ObjBase.pas:5762`、`:5834`。

### 待确认：半月「主目标不破防则剑气无效」

本视频 02:34 明确说：

> 虽然剑气可以对外围目标造成无视防御的伤害，但如果我们的正常物理攻击不能击破正前方目标的防御，那么周围的剑气是没有伤害的……因为大勇的防御是一百点，正前方的目标抵消了我们的伤害。

而 996 引擎实测（[BV1Dxxs6QE3e](./BILIBILI-BV1Dxxs6QE3e-warrior-skills.md)）结论相反：「计算被击中目标防御，但与主目标无关——主目标不破防也能打旁边小怪」。

火炬源码 `ObjBase.pas:5405-5411` 是在扣 AC 与命中判定**之前**就用原始 `dam` 算出 `seconddam` 并直接 `SwordWideAttack`，`seconddam` 恒 > 0，**没有「主目标破防」门槛**——即官服视频描述的行为在火炬源码里不存在。

结论：**两份外部资料互相冲突，项目与火炬源码同侧**。维持现状；若日后要复现官服手感，必须先找到 1.76 期原版 M2 的对应代码，不能凭视频改。

## 调优参考提示

- **可直接当基准线用的**：攻杀固伤 5/6/7/8、基本剑术 +3 准确、刺杀 40/60/80/100%、半月 15/23/30/38%、烈火 1.4/1.8/2.2/2.6——项目已全部对齐，改数值时以这组为锚。
- **值得修的**：野蛮步数（P1-1，涉及 PK 与堵门手感）、烈火 Round（P2，±1 点）。
- **不建议动的**：野蛮不能撞玩家、半月无破防门槛——前者是 PvP 位移表现缺失的取舍，后者是两份外部资料冲突且项目与火炬源码一致。
- **与 996 篇的差异**：烈火 996 口径为 56/108/176/260%，官服是 140/180/220/260%（仅满级相同）；半月 996 是 15/25/31/38%，官服是 15/23/30/38%。**项目取官服值**，与火炬 `HitDouble / PWideHitSkill` 公式一致，无需因 996 数据回调。
- **使用边界**：本视频是官服实机演示，不是 Delphi 源码；改代码前仍按 `jootm2-original-debug` 流程对火炬源码核实（本篇已核过一遍，行号见上）。
