# 离线挂机 + AI Bot 玩家 规划（Agent 引擎）

> 2026-11-18 规划稿。目标：朋友要求的**离线挂机**，以及后续用于活跃气氛的 **AI Bot 玩家**。
> 核心判断：两者共用同一套「代理引擎」——决策循环复用在线托管（AutoPilot），差别只在
> 「谁在驱动」和「收益归谁」。本文是总体规划，实施进度按轮次追加在文末。

## 一、现状盘点（可复用的家底）

| 能力 | 现状 | 位置 |
|---|---|---|
| 决策内核 | 选怪 → 寻路 → 攻击 → 拾取 → 喝药 → 补装备 → 背包整理 → 风筝/熔断，三档策略 | `pyserver/autopilot.py` |
| 寻路 | 服务端 8 方向 A*（图内），前端大地图点击导航也是图内 A* | `autopilot.py` / `frontend/map/pathfind.mjs` / `PlayScene.mjs _navPath` |
| 买卖 | `buyItem` / `sellItem` / `querySellPrice` 已直译原版语义（M2 goods 价格倍率） | `pyserver/handlers_npc.py` |
| 动作层 | 走/跑/攻击/施法/拾取/用物品全走现有 handler，自带时间锁与校验 | `service.py` 各 handler |
| 会话模型 | `Player.session is None` 即离线；世界广播天然兼容（`world.py` 大量 `if session is not None`） | `pyserver/world.py` |
| 清理点 | `service.on_disconnect` 是托管唯一清理点（离线挂机要在这里分叉） | `service.py:226` |

**关键缺口**：① 托管实例绑真人会话，动作层经 session 发包——离线没有 session；
② 只有图内寻路，跨图（回城买药、换图）没有链路表；③ 托管「绝不落库、断线即停」是
一期硬约束，离线挂机要打破它，需要新的生命周期与结算机制。

## 二、总体架构：一个引擎，三种驱动

抽一个 **AgentCore（决策循环）**，与「动作出口（ActionSink）」解耦：

```
                    ┌────────────────────────────┐
                    │   AgentCore（决策循环）      │
                    │  选怪/寻路/打/捡/喝/补/清/撤  │
                    │  （复用 autopilot.py 内核）   │
                    └──────────┬─────────────────┘
                               │ 每个决策周期输出「下一步动作」
              ┌────────────────┼────────────────────┐
              ▼                ▼                    ▼
        ActionSink:       ActionSink:          ActionSink:
        SessionSink       OfflineSink          BotSink
        （在线托管，       （离线挂机，          （AI Bot，
        现状，不动）       无 session，         虚构角色，
                          静默广播+落库）       氛围行为脚本）
```

- **决策层**与 session 无关：输入是 `Player` + 世界视图，输出是动作意图。
  现有 autopilot.py 的策略代码基本可平移；动作调用点从「直接调 handler」改为「经 sink 转发」。
- **动作层**三种出口：
  - `SessionSink`：现状，动作结果经 session 推给客户端，玩家看着托管打。
  - `OfflineSink`：没有客户端。广播照常发（其他在线玩家能看到 TA 在打怪），只是没人收；
    需要时把「离线报告」攒下来，登录时一次性展示。
  - `BotSink`：同 OfflineSink（Bot 也没有 session），额外接一个「氛围行为」上层：
    闲逛 / 定点卖萌 / 台词聊天 / 偶尔打怪，不打怪时走漫游决策。
- **收益归属**：托管→当前账号；离线挂机→账号（带收益系数与上限）；Bot→不落库，
  打怪产出直接丢弃或进「氛围掉落」白名单。

## 三、离线挂机设计

### 3.1 产品形态

- 玩家**在线时**配置：选地图（白名单内）、选时长（如 2/4/8 小时）、选策略档、
  勾「下线后继续挂机」；下线瞬间配置生效，角色**留在世界里真实打怪**（不是结算制）。
- 为什么选真实模拟而不是「离线收租结算」：
  ① 朋友期待的体验是「下线时在矿区，上线看到包里多了矿和药钱」，真实模拟才有可信度；
  ② Bot 一定要真实模拟（要在世界里被看见），共用引擎顺带解决离线挂机；
  ③ 死亡、被 PK、药耗尽等风险真实存在，天然形成资源竞争的边界。
- **上线接管**：登录时若离线挂机还在跑 → 立即结算停机，弹离线报告，交还手动控制。
  与在线托管同一原则：重登必须显式再开。
- **离线报告**（登录时展示一次，另存最近 N 条可查）：挂机时长、获得经验/金币、
  击杀数、拾取明细（前 10 条）、喝药消耗、死亡次数、停机原因。

### 3.2 生命周期（硬约束）

- **开启点**：玩家在线勾选并保存配置 → `characters` 表新增字段（`afk_plan` JSON：
  地图/时长/策略档/勾选）+ 新表 `afk_reports`（离线报告）。这是唯一落库的东西，
  运行状态（当前目标、动作计时）仍纯内存。
- **分叉点**：`service.on_disconnect` 不再一律清托管——若该角色有生效的离线计划，
  转交 `OfflineAgentManager`（新模块），Player 对象留在 `game_map.actors` 里继续 tick。
- **登录冲突**：`_login` / 选角入口检测「该角色正在离线挂机」→ 结算 → 移交 → 清理。
  同角色双开防护已有（`service.py:326`），复用。
- **停机条件**（任一触发即结算停机）：计划时长耗尽 / 喝药耗尽且血线危险 /
  背包满且回城卖货失败（v2）。
- **死亡处理（已拍板：自动复活）**：离线挂机死亡 → 按原版死亡结算（掉落照常）→
  回城复活 → 补状态 → 寻路回锚点继续挂。为防「药耗尽无限送死」，加**连死熔断**：
  同一次挂机内累计死亡 ≥3 次（可配 `afk.deathStop`）即停机结算，报告里列出死亡明细。
- **重启补偿（已拍板：重启自动续挂）**：当前更新/重启频繁，玩家不能每次重启都白丢挂机时间。
  设计：离线会话落库新表 `afk_sessions`（角色 id、计划分钟、剩余分钟、锚点图/坐标、
  策略档、状态），运行中每 60s 刷新剩余分钟；**服务端启动时扫描 `status=running` 的会话
  自动重新拉起离线代理**，从锚点继续挂、按剩余分钟继续消耗（不重扣），剩余 ≤0 则直接结算。
  补偿语义：重启最多丢最后一分钟内的进度；怪物/位置重置不追究。
  这同时解决「每次重启后玩家要重新配置」的痛点——玩家无感续挂。
  角色数据本体仍按原节奏落库；`afk_sessions` 剩余分钟是消耗记账的唯一事实源。
- **心跳与签到感**：结算用「实际挂机分钟数」而非「购买时长」，服务器宕机玩家不吃亏也不占便宜。

### 3.3 资源保护（用户原则，硬红线）

离线挂机会 7×24 占用刷怪资源、往经济里注水，必须设闸。
**全部做成 `config/server.properties` 可配置项**（进 `config.py::DEFAULTS`），
测试期默认值调低方便体验，公测前再收紧：

| 配置键 | 测试期默认 | 说明 |
|---|---|---|
| `afk.minLevel` | **15** | 开启等级门槛（用户已确认测试期降到 15 能体验；正式服建议 ≥30） |
| `afk.excludedMaps` | `0` | **黑名单**制（已拍板：放宽）：默认只禁比奇省(0) 新手区，其余地图都可挂；正式服可加长名单或改白名单 |
| `afk.perMapLimit` | 2 | 每张图离线代理并发上限，超出排队 |
| `afk.maxAgents` | 10 | 全服离线代理总量上限（tick 预算内），超出排队 |
| `afk.dailyMinutes` | 360（6h） | 每角色每日挂机总时长，跨 0 点重置 |
| `afk.expRate` | 0.7 | 离线经验系数（已拍板：可配，默认 0.7）；掉落/金币不打折 |
| `afk.lootSightCut` | 0.5 | 离线代理拾取视野系数（loot_sight 减半），给在线玩家留捡漏空间 |
| `afk.deathStop` | 3 | 单次挂机内累计死亡上限（防药尽无限送死） |

> 掉落归属照常（谁打归谁），不做「离线玩家掉落让给在线玩家」——那是偷玩家收益，
> 会引发纠纷。保护新手靠地图限制与等级门槛，不靠抢离线玩家的东西。

### 3.4 补给闭环（自动买药 / 卖货）

分两步走，MVP 先不闭环：

- **v1（无补给）**：带多少药打多少怪，药尽/背包满 → 停机结算。简单、无跨图风险。
- **v2（补给闭环）**：
  1. **跨图导航**：新增服务端「地图链路表」（map → 出口坐标 → 目标图），A* 逐段拼接；
     玩家配置挂机地图时，服务端预验证「当前所在图 → 白名单地图」可达，不可达不许开。
     前端大地图导航保持图内不动，跨图是纯服务端能力。
  2. **回城卖货**：背包剩 <4 格 → 寻路回城 → 找 NPC 卖肉/卖低价值装备（已有 sellItem）→ 买药补满
     （已有 buyItem）→ 寻路回挂机点继续。整条链每一步都走现有 handler 与时间锁。
  3. **熔断**：回城途中卡死 / 金币不够买药 / 连续 2 次补给失败 → 停机结算，报告里写明原因。
  4. 挂机点记忆：补给出发前记 `afk_anchor`（挂机图+坐标），补给完回到锚点。

### 3.5 性能与容量

- 每个离线代理 = 一个 tick 决策单元。现有 tick 100ms、单 asyncio loop、纯内存同步，
  参考在线托管的成本（几十个在线托管实测无压力），**离线代理总量建议上限 20 个**，
  超出排队。决策扫描做预算控制（`PATH_MAX_NODES` 已有上限，沿用）。
- 落库频率：离线期间角色数据**只在停机结算和每日 0 点快照时写库**（WAL 模式，
  避免每杀一怪写一次）；`afk_sessions.remaining_minutes` 每 60s 刷新一次，
  是重启续挂的记账事实源。

### 3.6 离线令牌发放机制（已拍板：从玛法领路人发放）

**形态决策：不做可交易物品，做角色级「离线修炼时长余额」。**
理由：项目当前没有物品绑定概念，做成道具必然可交易 → 被囤号倒卖/工作室批量收令牌，
等于给打金工作室开了官方入口。余额落在 `characters` 新列，天然与角色绑定。

- **落库字段**（`characters` 表新增）：`afk_minutes`（时长余额，分钟）、
  `afk_claim_date`（最近领取的服务器日期）、`afk_claim_count`（当日已领次数）。
  ⚠️ 每日限领**不能用 NPC 脚本的 `[n]` 标记实现**——`quest_params` 重登归零
  （`db.py:317` 已知坑，玛法领路人 5000 金可重领就是这个原因），必须走落库字段。
- **领取入口**：玛法领路人（`Npc_Def/玛法领路人-0.txt`，比奇 280,610）对话加
  「离线修炼补助」菜单项，领取规则全部可配（已拍板数值）：
  - `afk.claimMinutes`（默认 240）：每次领取 **+4 小时**余额；
  - `afk.claimPerDay`（默认 1）：每日限领次数（按服务器日期判断）；
  - `afk.poolCapMinutes`（默认 720）：余额上限 12 小时，防囤积。
- **新号赠送（已拍板：送）**：创建角色时直接入余额
  `afk.newbieMinutes`（默认 240，与单次领取同额）；落库即可，无需 NPC 领取，
  玛法领路人对话里显示当前余额方便玩家感知。
- **实现方式**：`NpcScriptEngine` 新增两个脚本命令——`giveafk <分钟>`（发余额，
  内部做日期/次数/上限校验并写库）与 `checkafk <比较式>`（脚本里判断等级/余额
  控制菜单文案）；改 `玛法领路人-0.txt` 加菜单分支。注意该脚本是 GBK 编码
  （`read_lines` 已自动探测，编辑时保持原编码）。
- **消耗模型：预扣 + 退回**。开启离线挂机时按计划时长从余额预扣，写入
  `afk_sessions.remaining_minutes`（§3.2）；提前停机（连死熔断/药尽/手动登录接管）
  结算时未用完的分钟数退回余额。重启续挂按 `remaining_minutes` 继续，不重扣。
  杜绝「开 8h 只挂 1h」的超支漏洞，也避免玩家因意外停机觉得白扣了。
- **调试**：GM 命令 `@afk grant <角色> <分钟>` 直接加余额（测试/补偿用）。
- **正式服方向**（提前预留，不在 v1 做）：若经济需要，后续可把「领取资格」挂钩
  在线时长/活跃行为（如在线满 1h 才能领当日补助），用离线时长反哺在线活跃，
  这是玛法领路人发令牌机制相比直接卖道具的最大可调空间。

## 四、AI Bot 玩家设计

### 4.1 定位与形态

- 目的：活跃气氛——城里有人走动、野外有人打怪、聊天频道有声音。
- Bot = `Player` 对象（`session=None`，加 `is_bot=True` 标记），**不落库、不进 characters 表**，
  重启由配置重建。名字池预置一批有年代感的 ID（如「热血战魂」「法海无边」）。
- Bot 也走 AgentCore + BotSink，但**默认行为是氛围优先，效率靠后**：
  - 城内：闲逛漫游（在锚点周边随机走）、偶尔停步、隔几分钟说一句台词
    （台词库按场景分：城里寒暄 / 卖装备吆喝 / 野外提醒「前面有精英怪」）。
  - 野外：低强度打怪（用 AgentCore 的 safe 档），打得慢、捡得少，像真人新手。
  - **聊天**：台词库 + 少量模板变量（`{地图}`、`{怪名}`、`{时间}`），v1 纯规则触发
    （定时 + 事件触发：有人升级/有人喊话时回应一句），不接 LLM。
- 与真人交互边界：Bot 可被攻击（真人杀 Bot 走正常 PK 规则，Bot 不报复、死了就回城复活），
  可交易/组队邀请一律礼貌拒绝（v1 直接忽略）。**Bot 决不抢怪**：选怪时跳过
  「已有真人目标锁」的怪——这是它和离线挂机最大的策略差异。

### 4.2 与离线挂机的同源关系

两者共用 AgentCore 与世界模拟，差异收敛为一行配置式定义：

| | 离线挂机 | AI Bot |
|---|---|---|
| 角色 | 真实账号角色，落库 | 虚构角色，不落库 |
| 驱动 | 玩家配置 + OfflineSink | 配置模板 + BotSink |
| 决策 | 效率优先（打怪/捡/卖） | 氛围优先（漫游/台词/低强度打怪） |
| 抢怪 | 允许（公平竞争） | 禁止（跳过真人目标） |
| 上限 | 每日时长 + 收益系数 | 全服数量上限（建议 5~8 个） |
| 死亡 | 停机结算 | 回城复活继续溜达 |

### 4.3 管理

- GM 命令：`@bot list / @bot add <模板名> / @bot remove <名字> / @bot say <名字> <台词>`。
- 配置文件 `gamedata/bots.json`：名字、职业、等级、外观 appr、装备皮、锚点地图、
  台词分组、性格参数（漫游半径、说话频率）。
- 上线顺序建议：先放 2~3 个「城里闲逛+寒暄」的最简 Bot 验证观感，再上野外打怪 Bot。

## 五、实施阶段（建议顺序）

> 每阶段独立可验收、独立提交；涉及托管共用的改动用 [托管] 标签，新增离线/Bot 用新标签
> （如 `[离线]` / `[机器人]`，提交时同步 CLAUDE.md 标签表）。

- **阶段 0：引擎解耦**（纯重构，零行为变化）
  autopilot.py 拆出 AgentCore（决策）与 SessionSink（动作出口）；在线托管改走 sink。
  验收：`test_autopilot*` 全绿 + 60s 真实挂机数据不退化。
- **阶段 1：离线挂机 MVP**
  OfflineSink + OfflineAgentManager + 生命周期（分叉点/登录接管/停机结算/**自动复活+连死熔断/
  重启自动续挂**）+ 落库（afk_plan / afk_sessions / afk_reports / 余额三列 + 新号赠送）+
  资源保护闸门（全部走 server.properties）+ 玛法领路人令牌领取（§3.6）+ 离线报告登录展示。
  v1 无补给闭环。
  验收：下线后经验继续增长、其他在线玩家能看到 TA 在打怪、
  15 级以下/黑名单地图拒绝开启、余额不足拒绝开启、每图超限被排队、
  玛法领路人每日限领与余额上限生效、新号自带赠送余额、死亡自动复活并回锚点、
  **重启后离线代理自动续挂且剩余分钟连续**。
- **阶段 2：补给闭环**
  跨图导航链路表 → 回城卖货买药 → 锚点回归 → 补给熔断。挂机时长从「一包药」变成「8 小时」。
  验收：满包自动回城卖货买药并回到锚点；金币耗尽停机且报告写明。
- **阶段 3：AI Bot（氛围版）**
  BotSink + bots.json + 城内漫游/台词 + 不抢怪策略 + GM 命令。
  验收：Bot 在城里走动说话、不挡真人任务路径、重启自动重建、数量上限生效。
- **阶段 4：打磨**（按实测反馈）

## 七、风险与待拍板项

**风险**
1. **经济通胀**是最大长期风险：离线挂机 + 补给闭环 = 半自动打金工作室形态。
   白名单地图要选「产出一般」的图（矿区/石墓够用但不产出顶级货），配合收益观察再放开。
2. **观感风险**：离线挂机本质是官方外挂，与「怀旧、手动」的调性冲突。
   建议文案定位为「离线修炼」而不是「离线挂机」，且严格限级限量，保持稀缺感。
3. **性能**：20 个代理 + 同图怪物 AI 在单 loop 内可承受，但白名单图怪物密度要在
   开服前实测 tick 耗时（加一个 tick 耗时统计点即可）。
4. **Bot 露馅**：固定台词 + 固定漫游路径会被玩家识别为假人。v1 接受露馅，
   台词库和漫游随机性按反馈迭代；不接 LLM（成本与合规都重）。

**拍板记录（2026-11-18，用户确认）**
1. 门槛数值：全部做成 `server.properties` 可配置项，测试期默认调低——15 级可体验、
   每图并发 2、全服代理 10、每日 6h（§3.3 表）。
2. 收益系数：可配，默认经验 ×0.7（`afk.expRate`）。
3. 地图限制：放宽为**黑名单制**，默认只禁比奇省(0)，其余可挂（`afk.excludedMaps`）。
4. 死亡处理：**自动复活**——原版死亡结算后回城复活、回锚点继续；加连死熔断（默认 3 次）。
5. Bot 首批：2 个城里寒暄 + 1 个矿区打怪，按 §4 实施。
6. 令牌发放：需要，从**玛法领路人**发放；机制见 §3.6（角色级时长余额，预扣+退回，
   每日限领+池上限，不做可交易道具）。
