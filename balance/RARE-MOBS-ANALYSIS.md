# high_drop.reset 黑名单的「稀有怪」误杀风险分析

> 2026-11-19，**纯分析，未改任何配置/代码、未提交**。回答用户两点质疑：
> 1. 黑名单里的怪是不是低刷新的稀有怪？若是不能误杀，应把「稀有」记为一种特性；
> 2. 若是稀有怪，balance 经济算法是否按「无限刷稀有怪」结算（算法有没有问题）。

---

## 结论先行

| 问题 | 结论 |
|---|---|
| 黑名单 35 只里有多少稀有怪 | **22 只（63%）理论供给 < 30/h**，其中 2 只完全没有刷怪点（供给=0） |
| 稀有怪该不该清高爆表 | **大概率不该**。稀有怪掉好东西是原版精英怪的正常设计；「供给低 × 单价高」的总产出被压在 31 万/h 以下，根本不是经济断崖来源 |
| balance 算法是否按无限刷稀有怪结算 | **没有这个问题**。`analysis.py:150` 已 `k_h=min(cap, supply)`，稀有怪被供给压低最多 864 倍；装备/经济链路都用的是约束后的 `kills_h` |
| 那断崖是怎么来的 | 来自**高频普通怪**（供给 150~900/h）被塞高爆表，如骷髅战士0 单只产出 2247 万/h——与稀有怪差 72 倍 |

**建议**：把「稀有怪」作为一级特性加入内容策略，黑名单按供给量分层——**只清普通怪的高爆表，稀有怪保留高爆**（或按更保守方案：全部保留，只清被确证为本项目魔改的）。

## 1. 刷怪脚本核查：22 只稀有怪

balance 的供给公式 `supply_per_hour = Σ count×3600/interval_s`。本分析定义**稀有 = 供给 < 30/h**（平均每 2 分钟不到 1 只）。

## 2. 关键区分：稀有 ≠ 高爆，两者是独立维度

黑洞般的断崖来自「**高频供给 × 高单价**」，不是「高单价」本身。按「原始单价 × 供给」算每小时总产出：

| 类别 | 最高每小时总产出 | 代表 |
|---|---|---|
| 稀有怪（22 只） | **31 万/h**（花吻蜘蛛0：14/h×22223） | 邪恶蝎蛇仅 1.99 万/h |
| 普通怪（13 只） | **2247 万/h**（骷髅战士0：901/h×24938） | 白野猪 1436 万/h |

**差 72 倍**。稀有怪掉高价装备是「稀缺性补偿」，是合理的游戏设计；清掉它们的高爆表 = 把精英怪降级成普通怪，属于误杀。

### 2.1 更麻烦的一点：多数稀有怪的高爆表是两棵树共有的

对比 main 与 176 数据树的 MonItems：

- `邪恶蝎蛇.txt` 78 行 **两树完全相同**
- `半兽勇士.txt` 54 行 **两树完全相同**
- `沃玛护卫.txt` 39 行 **两树完全相同**
- 花吻蜘蛛0 / 钢牙蜘蛛0 / 祖玛卫士00 两树**不同**，但 main 的版本是「金币+药水」低爆表、176 才是 `1/160` 装备表——即 main 反而更朴素

也就是说，这些稀有怪的高爆表**不是本项目单独魔改的**，是数据包历史遗留（甚至可能是原版精英怪设计）。按项目「找不到魔改依据不硬改」的约定，清它们依据不足。

## 3. balance 经济算法核查：没有「无限刷稀有怪」问题

逐层追踪计算链路（`analysis.py`）：

1. **`fight_rows:149-150`**：`supply = m.supply_per_hour() / max(1.0, n_same_band)`；`k_h = min(cap, supply)`，注释明确写「单人也受刷新上限约束（稀有精英怪尤其明显）」。
2. **供给约束效果**（以 ttk=5s 的理论上限 720/h 对比）：
   - 邪恶蝎蛇 0.83/h → 压低 **864×**
   - 祖玛卫士00 1.0/h → 压低 **720×**
   - 沃玛护卫 2.83/h → 压低 **254×**
   - 半兽勇士 9.3/h → 压低 **77×**
   - 而普通怪僵尸10(270/h) 只压低 3×、骷髅战士0(901/h) 根本不压
3. **`economy():200-209`** 用 `best(rows)` 选本级最优怪，rows 里 `exp_h/gold_h/loot_h` 全部基于约束后的 `k_h`。
4. **`gear` 装备获取**用 `b["kills_h"]`（第 237、304 行），同样是约束后的值。
5. **引擎 B**（真实地图 N 人）的 `kills_h` 来自实际击杀数，天然受刷新约束。

**结论**：经济算法已经正确处理稀有怪的供给上限，不存在「按无限刷稀有怪结算」。这一层不用改。

> 唯一可讨论的细节点：`n_same_band` 默认 =1，即单人独享该怪全服供给。多人同段时会按 `N×band_share` 分摊（第 282 行），逻辑自洽。

## 4. 建议的下一步（等你拍板，本次不动）

### 方案 A（推荐）：把「稀有」加入内容策略，分层处理

在 `content_policy.json` 增加 `rarity` 特性判定（用已有 supply 数据，不需新算法复杂度）：

```
"rarity": { "rare_supply_per_h": 30 },   // 供给 <30/h 记为稀有
"high_drop.reset": 只保留 13 只普通怪（其余 22 只稀有怪移出黑名单）
```

- 效果：保留稀有精英的高爆（原版合理），只清高频普通怪的私服高爆断崖。
- 代价：黑名单从 35 条缩到 13 条；稀有怪的高爆会进入经济表，但受供给约束不会造断崖（见 §3）。

### 方案 B（保守）：稀有怪高爆表整体保留，只清被确证魔改的

只清 176 树对照后确认「main 额外塞入」的条目；两树相同的（邪恶蝎蛇/半兽勇士/沃玛护卫）一律不动。

### 方案 C（最简）：维持现状

不改黑名单。代价是 22 只稀有精英被降级——若你在意原版精英怪体验，不建议。

**共同前提**：无论哪个方案，balance 经济算法都不用动（§3 已证）。
