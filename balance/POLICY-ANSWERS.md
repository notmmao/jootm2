## 问题 2：剥离我本沉默数据的方案（不删文件、可开关、便于扩展、45 级封顶）

### 设计原则

1. **不物理删文件**：原始 `gamedata/` 保持完整（可随时恢复、便于后续扩展沉默内容）；
2. **加载期过滤**：在"CSV → SQLite/内存模板"这一层加一个**集中式过滤模块**，启动时按清单剔除；
3. **配置化清单**：剥离名单单独放一个声明式文件，改一行就能加回/去掉某项；
4. **一处开关**：一个总开关控制启用/关闭，默认关闭（保持现状），你确认后再打开；
5. **45 级封顶**：单独的等级上限规则，与内容剥离解耦。

### 服务端数据加载链路（已实测确认）

```
启动 → db.py::_import_csv()  从 gamedata/mud2/DB/{StdItems,Monster,Magic}.csv 重灌三张模板表（每次启动都重灌）
     → world.py::__init__()  parse_map_info(MapInfo.txt) / parse_mon_gen(MonGen.txt) / scan_available_maps()
     → world_extra.py::init_extra()  load_drop_tables(MonItems/*.txt) / load_npc_spawns(Npcs.txt) / 商店脚本
     → world.py::NEED_EXPS 硬编码 101 级经验表
```

**所有内容都从文件加载进内存**，没有其他地方硬编码我本沉默条目 → 过滤层有唯一收敛点，方案可行。

### 推荐方案：`config/content_policy.json` + `pyserver/content_filter.py`

**① 配置文件（人可读、可注释扩展）**

```json
{
  "enabled": false,
  "max_level": 45,
  "drop_items":    ["*域*戒指", "蓝灵*", "爱情鲜花", "死亡纹章", "天外飞石", "绿玉屠龙", "嗜血法杖", "七星法杖", "..."],
  "drop_monsters": ["驽马*", "*蟾怪", "火蚁", "兵蚁", "毒蚁", "工蚁", "蚁后",
                    "沃玛统领", "骷髅统领", "蝎蛇统领", "钳虫统领", "半兽统领", "猪卫统领", "蝎卫统领",
                    "虹魔蝎卫", "虹魔猪卫", "千年树妖", "恶魔弓箭手", "雪人王", "多钩猫王", "钉耙猫王", "剧毒蜘蛛"],
  "drop_maps":     ["D2051-D2067", "月崕岛", "不归路", "兽人古战场", "潜龙峡谷", "相思墓穴", "埋没之城", "静寂神庙", "避世森林", "邪恶之都", "死亡棺材", "牛魔教堂"],
  "drop_npcs":     ["老渔翁", "地魔"],
  "high_drop_monsters": ["僵尸1*", "僵尸4*", "僵尸5*", "黑野猪0", "骷髅0", "蜈蚣0", "残尸0", "腐尸0", "黑锷蜘蛛0", "..."]
}
```

`*域*` 等 glob 模式便于扩展；`high_drop_monsters` 单独一组，因为它们是**官服怪的技术变体**（见问题3），剥离时要保留显示名对应的官服怪、只踢掉高爆变体。

**② 过滤模块 `pyserver/content_filter.py`**

提供 `should_drop_item/monster/map/npc(name) -> bool` 和 `patch_drop_entry()`，加载时挂载到四个收敛点：

| 收敛点 | 改动 | 效果 |
|---|---|---|
| `db._import_csv` | 读入三表后按清单过滤再插入 | 物品/怪/技能模板不再存在 |
| `world.__init__` | `mon_gen_entries`、地图标题、gates 过滤 | 沉默地图/怪不刷新、不可达 |
| `world_extra.load_drop_tables` | MonItems 条目：物品被禁→删条目；高爆怪→整表降到官服基线变体表 | 断崖产出消失 |
| `world_extra.load_npc_spawns` | NPC 列表过滤 | 老渔翁/地魔不出现 |

**③ 45 级封顶（两处，解耦）**

- `level_cap`：玩家 `exp_for_level`/`gain_exp` 到 45 级不再涨（保留 45 级封顶提示）；
-  monsters 里 level>45 的模板按清单过滤（或保留但不刷+不可达）。

**④ 验证**

- 加 `scripts/test_content_filter.py`：断言开启开关后上述条目全部不在模板表/刷怪表/NPC 表；
- 用 `balance/run.py report` 复跑，确认法师21/道士33 断崖消失（这是方案生效的量化证据）；
- 服务端 `python -m pyserver` 启动无异常、老账号（可能有超 45 级/被禁物品）需加一条迁移兜底：登录时把被禁物品回收为金币、等级钳到 45。

### 方案优点 / 待你拍板的点

- ✅ 原始数据零改动，随时 `enabled:false` 一键恢复；
- ✅ 新增沉默内容只需往 JSON 加一行；
- ✅ 断崖怪、产金怪一并处理，经济回归官服形态。
- ❓ **待定**：`high_drop_monsters`（官服怪的高爆变体）是"连变体一起删"还是"保留怪、只清空其高爆掉落表"？我建议后者——玩家看到的仍是"僵尸"，只是不再爆 1/3 装备，符合官服体验。
- ❓ **待定**：45 级封顶是"完全不能升过 45"还是"能升但经验表按 45 截断"？需明确已有 45+ 老账号如何处置。

> 这是方案设计，**我没有改任何现有代码**。你确认这两点后我再实现。

## 问题 3：导致产出/经验断层的怪，是"赖在我本沉默系统"吗？

**答：要分两层看——名字/ID 是官服怪，但高爆掉落表是我本沉默私服数值。断层的根源在"我本沉默"，不在官服，也不在计算公式。**

我在上一轮的 `ECON-SPIKE-ANALYSIS.md` 里把"数字后缀变种怪（僵尸10等）"直接归为沉默私服内容——**这个说法不精确，本轮修正**：`pyserver/world.py:167-179` 明确写出，数字后缀是**本项目把 Monster.DB 同名多变体转成 Monster.csv 时，为 key 唯一加的技术后缀**；`filter_show_name` 会把"僵尸10"显示成"僵尸"。所以：

| 层 | 归属 | 证据 |
|---|---|---|
| **名字 / 外观 / 基础属性** | ✅ 官服怪（僵尸、黑野猪、骷髅…） | `僵尸10` 的 appr=40、exp=480 与官服僵尸一致；显示名截断成"僵尸" |
| **高爆掉落表** | ❌ 我本沉默私服数值 | 同为 appr40 僵尸：`僵尸1` itemval=**49**，`僵尸10` itemval=**7245**（差 148 倍）；`僵尸10.txt` 原始写 `1/3 黑色水晶项链`、`1/5 凌风`——官服僵尸只掉基础书/小极品，绝无 1/3 掉率 |

**所以断层的因果链是**：
1. 官服有一只普通怪"僵尸"（官服内容，保留）；
2. 我本沉默数据包给它加了一份"高爆变体"（`僵尸10`，itemval 7245）；
3. 分析工具按"本级净收入最高"选怪，法师21刚好选中 `僵尸10` → 每小时 loot 190 万 → 断崖。

**结论**：
- 断层**不是计算 bug**（上轮已证），也不是官服设计——是**我本沉默塞进来的高爆变体造成的**；
- 因此问题 2 的剥离方案一旦执行（清掉这些高爆变体的掉落表），**法师21/道士33 的断崖会自然消失**，无需单独修数值；
- 断崖怪（僵尸10/黑野猪0/残尸/腐尸）的"壳"是官服的，"心"（掉落）是沉默的——剥离时要**保留壳、换心**，这正是方案 2 里 `high_drop_monsters` 单独成组的原因。
